## Quick resume

`augur` is a Stellaris campaign advisor living at `~/Theta/augur`. It parses a
save locally and prints campaign state for Claude Code to reason over — no API
key, no MCP server. It is a cannibalized fork of
[gitmaan/stellaris-companion](https://github.com/gitmaan/stellaris-companion)
(MIT). Four commits on branch `ccr-eff029cb-4ku8q2`, open as draft PR
[7uk0/Theta#1](https://github.com/7uk0/Theta/pull/1). 301 tests pass, lint clean.

**The whole reason to be local:** nothing in this project has ever touched a real
Stellaris save. Everything was verified against a hand-built synthetic one,
because the cloud container could not see Wolf-Box. That is the top of the next
steps list.

Read `~/Theta/CLAUDE.md` first — it is the durable memory and carries the
architecture, non-negotiables and hard-won gotchas.

<context>
The User is building a home lab ecosystem around Theta, a local AI on OpenWebUI.
`augur/` is one flow in the `Theta` monorepo: it reads a Stellaris `.sav`, tracks
what changed between saves in SQLite, and prints a briefing that Claude Code
turns into strategic advice in the empire's voice. The fork exists because
upstream requires a paid model endpoint (Gemini/OpenRouter) or an MCP server, and
paying for an API key for a hobby project was not worth it — so the model client
was amputated and replaced with stdout. The stated end goal is **everything
local**; this design already serves that, since `augur brief --json` is
model-agnostic and Theta on OpenWebUI could read it later with a thin adapter.

<progress>
Four commits, each verified before pushing:

- **The port.** Kept ~26.6k lines (the Rust Clausewitz parser, the extraction
  suite, database/history/events/signals, and `context.py` — upstream's MCP tool
  layer with the JSON-RPC transport peeled off). Cut ~26k (Electron app with
  8-language i18n, FastAPI backend, Cloudflare Discord relay, the
  Gemini/OpenRouter/Ollama provider stack, the API-model Chronicle generator, the
  MCP server and its bundle, release packaging). The cut was decided by an AST
  import-closure walk rather than by reading directory names, which is why
  dependencies fell from ten to **two**: `orjson` and `watchdog`.
- **Memory.** `CLAUDE.md` and `augur/docs/PORT-NOTES.md`. Cloud sessions have no
  memory directory and the container is reclaimed, so committed files are the only
  durable context. CLAUDE.md auto-loads in every future session on this repo.
- **The orrery** (`augur dash`). A curses dashboard — what the cut Electron app
  was for. Chosen as stdlib `curses` specifically to avoid adding `rich` or
  `textual` and breaking the two-dependency rule. Its accent colour is derived
  from the empire's own ethos (crimson militarist, cold cyan machine
  intelligence, olive hive mind, violet spiritualist), verified by reading back
  real terminal colours through a pty.
- **A three-agent bug hunt and its fixes.** Three subagents audited the new code,
  the port seams, and the docs/skill against reality. ~45 findings; the real ones
  were fixed with a test each. The worst were silent: two concurrent ingests
  forked the campaign into two sessions permanently; quitting the dashboard during
  an ingest lost the autosave; the save-stability guard returned True on timeout
  while documenting the opposite; `augur chronicle source --json` exited 2, which
  is step one of the only Chronicle write path in the skill. Tests went 108 → 301,
  because 189 upstream tests covering kept modules had simply never been
  ported — including snapshot dedupe, the archive's only write path, previously
  asserted nowhere.

Decisions worth not relitigating:

- `context.py` is the seam the fork hangs on — ten methods, no transport
  coupling. The CLI is one caller, not the owner. Keep it that way.
- The dashboard is a second *consumer* of the same context, which is how the
  `sections`-nesting bug was found at all. Having two readers is load-bearing.
- Pane names are in-universe (EMPIRE / RESOURCE LEDGER / TRAJECTORY / SITUATION
  LOG). "Situation Log" is an actual Stellaris UI panel.
- The patch-notes corpus was 840 lines of dead code the docs called live. It is
  now reachable as `augur knowledge`, selecting mechanics for the save's own game
  version, rather than being deleted.
</progress>

<constraints>
Non-negotiable, from `CLAUDE.md`:

- **No model client, ever.** No API keys, no provider SDKs, no `google-genai`, no
  `openai`. Two dependencies; a third needs a real reason. The entire point is
  that Claude Code is the model.
- **No MCP server.** The commands are the interface.
- `augur vigil` and `augur dash` run until interrupted. Never start either in the
  foreground of a session — tell the User to run them in their own terminal.
- Chronicle writes require `campaign_ref` + `chronicle_revision` from a *fresh*
  read. They are concurrency guards. Never write without an explicit request from
  the User; draft, show, wait to be asked.
- Ingest is serialised by `augur.ingest._INGEST_LOCK`. Never bypass it.
- Thread writers must be joined before the database closes
  (`Dashboard.shutdown()` is the pattern).
- Never push to `main`. Branch `ccr-eff029cb-4ku8q2` for this work.

User communication preferences, learned directly:

- **Be brief.** The User said, verbatim: *"You gave a lot of text page is worth so
  I need you to tell me because I read like half of what you just said."* They are
  often on a phone. Lead with the answer; skip the preamble.
- When troubleshooting or giving step-by-step guidance: clear, direct, functional
  only. No philosophical or abstract content.
- When brainstorming or exploring: warmth and genuine connection-drawing is
  welcome, including the esoterica/technology parallels, but never forced.
- Naming leans esoteric — divinatory, alchemical, psychedelic — *where it does not
  cost clarity*. Subcommands stay guessable; flavoured aliases are extra
  (`scry`→`brief`, `omens`→`events`, `orrery`→`dash`).
- Address them as **User**.

Platform: Wolf-Box, Debian 13 Trixie, Ryzen 7 3700X, RTX 3060 Ti, 3440x1440
ultrawide, Xfce4/Chicago95.
</constraints>

<open_threads>
**Verified-but-unfixed bugs.** Both reproduced; left for a local session rather
than widening the last commit:

1. `CampaignContext()` and `GameDatabase()` with no arguments ignore `$AUGUR_DB`
   and the XDG archive, defaulting to `./stellaris_history.db` and littering an
   empty 118 KB database in whatever directory you are in. The real path policy
   lives only in `augur/cli.py:resolve_db_path`, while
   `augur/core/database.py` has its own stale one (`DEFAULT_DB_FILENAME`,
   `STELLARIS_DB_PATH`). `augur/context.py`'s own docstring invites the mistake:
   *"a Python script or a test is just as valid a one."* The policy belongs in
   `database.py` or `parser/paths.py`, next to `get_state_dir()`.

2. `--language de` makes an existing Chronicle **invisible** and lets you write a
   parallel one that the default scope never shows. One flag serves two unrelated
   concerns: the locale of the advice (useful) and the Chronicle's storage
   partition key (a trap). Nothing in `--help`, the README or the skill says the
   flag moves the Chronicle. Either split the two concerns or warn loudly.

**Known gaps, deliberately not built:**

- `advisor_memory` and `advisor_custom_instructions` are read into every briefing
  and have three paragraphs of guidance about them, but **no writer exists** — the
  upstream writers were in deleted files. The feature describes itself and cannot
  be turned on. `tests/test_context.py` asserts them only because its fixture
  calls the orphaned DB methods directly.
- Nine campaign/playthrough management methods (list, label, trash, restore,
  delete, reset chronicle, undo reset, backup) work and are covered by 11 tests,
  but no CLI command reaches any of them. A User with two campaigns in one
  archive has no way to switch or label them.
- `record_snapshot_from_companion` in `augur/core/history.py` is a dead ~90-line
  near-duplicate whose docstring points at `ingestion_worker`, a module that was
  never ported. Comments there will send a maintainer looking for nothing.
- The dashboard needs 72x11 minimum. Below that it says so rather than drawing a
  mangled frame. A single-column layout for narrow panes was considered and
  skipped.
- A "phone bridge" was proposed and not built: Wolf-Box pushing a rendered
  briefing to a branch so a phone session could read it. It costs putting campaign
  state in the repo, which is the User's call. Moot now that work is local, unless
  they want it.

**Unanswered question put to the User:** the root `README.md` starts with the
literal text `<Theta>`, which GitHub's sanitiser drops, so the page renders
untitled. It is their text and was left alone. They never answered whether to
change it to `# Theta`.

**Housekeeping:** this cloud session has a `send_later` check-in armed against PR
#1 and is subscribed to its GitHub activity. Both become noise once work is local
and the PR is merged.
</open_threads>

| What | Where | Override |
| --- | --- | --- |
| Campaign archive | `~/.local/state/augur/campaign.db` | `--db`, `$AUGUR_DB` |

| Project root | `~/Theta/augur` | `$AUGUR_HOME` |

Permissions note: `.claude/settings.json` is **project-scoped**, but `install.sh`
links the skill into `~/.claude` so it works from any directory. Running `claude`
outside `~/Theta` triggers the skill with nothing pre-approved, so every `augur`
call prompts. Either run from `~/Theta` or copy the allow-list into
`~/.claude/settings.json`.

Do not rename: `augur/context.py` seeds the campaign digest with the literal
string `"stellaris-companion:{save_id}"`. Changing it re-keys every
`campaign_ref` and invalidates every stored Chronicle write guard.
